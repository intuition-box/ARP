# For developers

## The repository

```
apps/        what runs
  cli/       @arp-protocol/cli: the MCP server, the hook and the node in one `arp` binary
  mcp/       the MCP server: reads the graph, prepares unsigned calls, runs the search
  hook/      the runtime hook: records which skills and MCP tools a session used; reads GitHub only before a skills install
  node/      the hire endpoint: checks a payment, signs a receipt
  sponsor/   the sponsoring service that pays testnet fees for agents (testnet 13579 only)
  web/       the web app
  probe/     Cloudflare Worker: asks listed MCP endpoints whether they answer
  api/       Cloudflare Worker: GitHub's and skills.sh's figures, cached and dated
packages/    what is imported
  protocol/  @arp-protocol/core: identity, graph reads, the search's score, unsigned call plans
  graphql/   @arp-protocol/graphql: the Intuition queries
contracts/   Solidity, Foundry
packaging/   generated by apps/cli: the Claude Code plugin and the Gemini extension. Do not edit
skills/arp/  the ARP skill, for an agent with nothing installed
data/        the catalogue, the deployments per chain, committed measurements
scripts/     the maintainers' own tooling: seeding, measuring, demos
docs/        the mechanism, the decisions, the guides
```

## Build and test

You need [Bun](https://bun.sh) 1.2 or later, Node.js 22 or later and [Foundry](https://book.getfoundry.sh).

```bash
git clone https://github.com/intuition-box/ARP.git
cd ARP
bun install --frozen-lockfile
bun run --cwd contracts deps      # the contracts' git submodules; `bun run test` needs them
bun run check                     # scripts typecheck, the web app's tokens and contrast
bun run lint
bun run test                      # every workspace, the contracts with forge, then scripts/
bun run build
bun run dev                       # the web app on http://localhost:5173
```

The CLI and the plugin:

```bash
bun run --cwd apps/cli build             # apps/cli/dist/cli.js and dist/hook.js
bun run --cwd apps/cli check:node        # the build, run under Node 22 without Bun
bun run --cwd apps/cli packages          # rewrites packaging/ and .claude-plugin/
bun run --cwd apps/cli packages --check  # fails if packaging/ is out of date
```

To try a local build of the plugin in Claude Code, point the marketplace at your checkout: `claude plugin marketplace add ./` from the repository root, then `claude plugin install arp@arp`.

Copy `.env.example` to `.env` before anything that writes to a chain. Reading needs no key.

## What is published

Only **`@arp-protocol/cli`** is on npm. `@arp-protocol/core` and `@arp-protocol/graphql` are workspaces of this repository and are not published: import them from a checkout.

The Claude Code plugin is not on npm. It is `packaging/claude/arp/`, listed by `.claude-plugin/marketplace.json` at the repository root, which is what `claude plugin marketplace add intuition-box/ARP` reads. It carries the CLI as one file, `bin/arp.js`.

Three dated feeds are served from this site under `/feeds/`, readable from any origin, each rebuilt by a script in `scripts/build/`: [the x402 outcomes feed](/docs/x402-feed) (`x402-outcomes.json`), [the skill lines feed](/docs/skill-lines-feed) (`skill-lines.json`) and [the agent sieve feed](/docs/agent-sieve-feed) (`agent-sieve.json`).

## The MCP tools

The server serves one of three sets, chosen by `ARP_TOOLS`:

| `ARP_TOOLS` | Set by | Tools |
| --- | --- | --- |
| `read` | the Claude Code plugin | `arp_pulse`, `arp_tool_reputation`, `arp_agent_endpoints` |
| unset | `arp init` | the full set: `arp_pulse`, `arp_find_tools`, `arp_find_agents`, `arp_tool_reputation`, `arp_agent_endpoints`, `arp_identity`, `arp_probe_endpoint`, and the planners `arp_declare_used`, `arp_declare_session`, `arp_stake_on_used`, `arp_take_position`, `arp_exit_position`, `arp_record_reachable` |
| `desktop`, `sponsored` | the Claude Desktop extension, `arp init --sponsored` | `arp_pulse`, `arp_find_tools`, `arp_find_agents`, `arp_tool_reputation`, `arp_agent_endpoints`, plus `arp_get_skill` and a sponsored `arp_declare_used`. `arp_pulse` runs no search package here: it reads results you pass it |

The main inputs:

| Tool | Required | Optional |
| --- | --- | --- |
| `arp_pulse` | none | `queries` (up to 4 short phrases) or `query`, or `search_output` when the host cannot run the search; `domain`; `constraints` (`no_keys`, `no_login`, `no_paid`, `no_scripts`, `have_commands`, `can_provide`); `limit` 1 to 20 |
| `arp_tool_reputation` | `tool_atom_id` | `attested_by` |
| `arp_agent_endpoints` | `agent_chain_id`, `agent_token_id` | `registry` |
| `arp_find_tools` | none | `query`, `domain`, `order`, `limit`, `offset`, `detail`, `curve_id` |
| `arp_find_agents` | none | `domain`, `order`, `limit`, `offset` |
| `arp_identity` | `agent_chain_id`, `agent_token_id` | `registry` |
| `arp_probe_endpoint` | `url` | `protocol` |
| `arp_declare_used` | `agent_chain_id`, `agent_token_id`, `tools` | `domain`, `outcome`, `reason`, `budget_wei`, `declarer`, `registry` |
| `arp_declare_session` | `agent_chain_id`, `agent_token_id` | `log`, `declarer`, `registry` |
| `arp_stake_on_used` | `receiver`, `targets` | `curve_id` |
| `arp_take_position` | `term_id`, `amount_wei`, `receiver` | `curve_id`, `min_shares` |
| `arp_exit_position` | `term_id`, `account`, `receiver` | `shares`, `curve_id`, `min_assets` |
| `arp_record_reachable` | `url`, `tool_atom_id`, `receiver` | `protocol` |

The schemas, with every description, are in `apps/mcp/src/tools.ts`. A planner returns unsigned calls. The server holds no key that signs them: you sign them with yours.

## Reading the graph

Everything ARP reads is public, on Intuition's index. No key, no account:

```bash
curl -s https://testnet.intuition.sh/v1/graphql \
  -H 'content-type: application/json' \
  -d '{"query":"{ atoms(limit: 1) { term_id label } }"}'
```

Mainnet 1155 is `https://mainnet.intuition.sh/v1/graphql`. The chain's RPC, explorer and contract addresses are in `data/deployments/13579.json` and `data/deployments/1155.json`. Costs such as `getTripleCost()` are read from the contract, not from those files. The queries ARP itself runs are in `packages/graphql/`, and `skills/arp/SKILL.md` gives the three an agent needs with nothing installed.

## Environment variables

Every variable read in `apps/*/src` and `packages/*/src`, found by a grep of `process.env`, `env[...]` and the services' own readers on 2026-11-09. `scripts/` reads more, documented in each script's header.

### The MCP server (`arp mcp`, `apps/mcp`)

| Variable | Default | What |
| --- | --- | --- |
| `ARP_TARGET` | `mainnet` | `testnet` (13579) or `mainnet` (1155). The plugin and `arp init` set `testnet` |
| `ARP_TOOLS` | unset, the full set | `read`, `desktop` or `sponsored` |
| `ARP_TRANSPORT` | | `stdio`, same as `--stdio` |
| `ARP_HOME` | `~/.arp` | where every program keeps its state |
| `ARP_PROJECT_DIR` | the working directory | the project relative paths mean. Set by the `npx` launch |
| `ARP_SESSION_LOG` | `.arp/session.jsonl` | the hook's log |
| `ARP_RECEIPTS` | `.arp/receipts.jsonl` | the receipts of fetched skills |
| `ARP_SKILLS_DIR` | unset | sponsored only: where an accepted skill is installed. `arp init --sponsored` sets `.claude/skills` |
| `ARP_PULSE_SEARCH` | on | `off`: `arp_pulse` runs no package and takes `search_output` only |
| `ARP_PULSE_SCORE` | on | `off`: `arp_pulse` keeps the search's own order and computes no score |
| `ARP_DOMAIN_ATTESTOR` | ARP's two addresses | whose domain tags to read, comma-separated |
| `ARP_MULTI_VAULT`, `INTUITION_GRAPHQL_URL`, `INTUITION_RPC_URL` | the chain's deployment record | where it reads |
| `ARP_RECEIPT_KEY` | generated in `~/.arp/receipt-key` | a key you manage for content receipts. Never a funded one |
| `ARP_NO_RECEIPTS` | unset | `1`: run with no receipt key |
| `ARP_ACCEPTED_SIGNERS` | empty | receipt signers this server accepts, comma-separated |
| `ARP_CONTENT` | `http://127.0.0.1:3002` | sponsored only: the content server |
| `ARP_SPONSOR` | `http://127.0.0.1:3200` | the sponsoring service, for the sponsored setup, `arp line` and `arp share send` |
| `ARP_ALLOW_PRIVATE_PROBE` | unset | `1`: let a probe reach a private address |
| `PORT`, `ARP_HOST`, `ARP_ALLOWED_HOSTS` | `3002`, `127.0.0.1`, none | `arp mcp --http` only |
| `ARP_CHAIN_ID` | `13579` | which chain's catalogue `apps/mcp/src/session-log.ts` reads |
| `ARP_ACTIVITY_DIR`, `ARP_ACTIVITY_PORT`, `ARP_ACTIVITY_ORIGINS` | `.arp`, `3003`, none | `session-log.ts --serve` only: the local activity feed |
| `ARP_NODE` | `http://localhost:3002` | `apps/mcp/src/fetch-skill.ts` only: the content server to fetch from |
| `ARP_AGENT_PRIVATE_KEY` | unset | `fetch-skill.ts` only: a key that signs one off-chain request, so the receipt names the agent. Never a funded one |
| `GITHUB_TOKEN` | unset | raises GitHub's limit of 60 requests an hour, and adds repository figures |

### The web app (`apps/web`, read at build time)

`VITE_INTUITION_TESTNET_RPC_URL`, `VITE_INTUITION_TESTNET_EXPLORER`, `VITE_WALLETCONNECT_PROJECT_ID`, `VITE_MAX_STAKE_TRUST`, `VITE_ARP_API_URL`, `VITE_ARP_ACTIVITY_URL`, `VITE_ARP_SPONSOR_ADDRESS`, `VITE_ARP_SPONSOR_URL`, each explained in `.env.example`. A `VITE_` variable ends up in the page every visitor loads: never put a key in one.

### The Workers (`apps/api`, `apps/probe`)

`apps/api` reads `GITHUB_TOKEN`, `REFRESH_SECRET` and `REFRESH_EVERY_HOURS` (set to `24` in `wrangler.jsonc`). `apps/probe` reads no variable. Both use Cloudflare bindings (`FACTS`, `PROBES`) declared in their `wrangler.jsonc`.

### Deploying and scripts

`.env.example` also holds `PRIVATE_KEY`, `AGENT_PRIVATE_KEY`, `AGENT_ADDRESS` and `ETHERSCAN_API_KEY`, which the contract deployments and `scripts/` read. Use keys that hold test money only.

## Contributing

- **Open an issue first** on https://github.com/intuition-box/ARP/issues for anything beyond a small fix, so we can agree on the scope.
- **Commits are conventional**: `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`, with a scope when it helps (`fix(cli): …`). One logical change per commit, its tests with it.
- **Before a pull request**, run `bun run check`, `bun run lint` and `bun run test`, and `bun run --cwd apps/cli packages --check` if you touched `apps/cli`, `apps/mcp` or `apps/hook`.
- **Tests come with the code.** A service function gets a unit test, mocked at the network boundary only. A contract change gets Foundry tests for every revert path.
- **Nothing in a test or a script signs on mainnet.** Raw-key signing in `scripts/` is refused on any chain but testnet 13579, except contract deployment, which needs an explicit `--mainnet-i-confirmed`.
- **Never commit `.env`**, a key, or an RPC URL that carries one.
- **A number in a document names the script that produces it.** `scripts/measure/` holds them.
